# Jira Ticket Template

The template, verbatim:
```
**Who** <who wants to change something (which entity, user, etc.)>
**What** <what needs to be changed (short one liner)>
**Why** <why the change needs to happen now (short one liner)>


**Additional Context**
* <if the why one liner above is not sufficient, add more context here as bulletpoints>


**Functional Details**
* <write details as bullet points>


**Technical Details**
* <write details as bullet points>


**Deliverables**
* <write a list of deliverables as bullet points>


**Acceptance Criteria**
* <one criterium per bullet point>


**Important Notes**
* <write notes as bullet points>
```


Section rules:

| Section | Required | Notes |
|---|---|---|
| Who | no, optional | Who requested the change, only include if it is a very clear user request. |
| What | yes | What needs to be changed. |
| Why | yes | Why the change needs to happen now. |
| Additional Context | no, optional | More context that is not sufficient in the why. |
| Functional Details | yes | What needs to be done to make the change. |
| Technical Details | yes | Repos, files, functions, endpoints, where the code lives. |
| Deliverables | yes | Items that will be delivered (eighter physical documents/scripts or descriptions of core functionality). Make this as concrete as possible, save the more conceptual stuff for the acceptance criteria. |
| Acceptance Criteria | yes | One testable criterion per bullet. |
| Important Notes | no, optional | Pitfalls, gotchas, points of attention. |
